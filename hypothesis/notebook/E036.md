H4.3.1 (open, c=0.45): With the Muon update compiled without max-autotune (mode='default') and cuDNN algorithm selection pinned (cudnn.benchmark=False or deterministic algorithms for the 16/24/32 px shapes), two identical runs of the tip give bit-identical per-seed accuracies, with time within +1.5% of 5.50 s.
H4.3 (open, c=0.45): The tip's run-to-run non-determinism (E028) comes from per-process autotuning: max-autotune configs for the compiled Muon update (bmm, Triton reductions), or cuDNN/Inductor algorithm picks for the newer 16/24 px shapes. The SGD 32 px recipe compiled the same way was bit-identical (E002). Pinning these choices in build restores determinism, which makes seed-paired comparisons possible again and roughly halves the noise on a difference between two runs.
H4 (open, c=0.70): Accuracy and timing noise set the usable margin. The compiled SGD recipe is bit-deterministic per seed (E002). The compiled-Muon progressive tip is not (E028): an identical rerun moved single seeds by up to 0.59 pp and the 3-seed mean by 0.22 pp. For tip-like recipes the run-to-run sd of the 3-seed mean is about 0.15 pp, so the sd of a difference between two single runs is about 0.2 pp. Gaps under about 0.4 pp are not resolvable from one run each. Best tip estimate (E026 code): 0.7554 on seeds 0-2 (E026 and E028 averaged) and 0.7553 over 11 seeds (seeds 3-10 mean 0.7553, sd 0.22 pp). The official 40-seed mean should therefore clear 0.75. Rule for a new tip: a 3-seed mean of at least 0.755, or two runs averaging at least 0.7535. Time noise is about 0.1-0.5%.
Idea: Determinism probe on the E026 tip, with no change to the math or hyperparameters. Compile the Muon update with mode='default' instead of 'max-autotune-no-cudagraphs', and set torch.backends.cudnn.benchmark=False with cudnn.deterministic=True for all train/eval shapes. Keep the net's own compile as is. Warm everything up in build. Run the scored evaluation, then rerun seed 0 once in an untimed side script through the benchmark's trial code and compare per-seed accuracy bit for bit.

accuracy 0.75577 (0.7549, 0.7559, 0.7565) vs tip 0.7572 (noise); time 6.008 s vs 5.472: +9.8%. Untimed seed-0 rerun

The two changes were bundled: (a) Muon update compiled in default mode instead of max-autotune-no-cudagraphs,
(b) cudnn.benchmark=False + cudnn.deterministic=True. (b) is almost certainly the +9.8% (default cuDNN algorithms for
the net's convs instead of benchmarked ones). Cheap follow-up: (a) alone, keeping cudnn.benchmark=True -- if that is
still deterministic, the nondeterminism came from the Muon autotune picks and determinism is ~free.

### Post-mortem
Predicted time [5.47, 5.62] -> miss (6.008, +9.8%). Root cause: I underestimated the cost of disabling cuDNN
benchmarking -- default algorithms for these conv shapes (incl. 16/24 px) are much slower than benchmarked ones.
Determinism itself was achieved. Lesson: bundle-free probes -- test the cheap candidate cause (Muon compile mode)
alone before paying for cuDNN determinism.
