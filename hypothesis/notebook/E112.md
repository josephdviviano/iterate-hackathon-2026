H12.2 (open, c=0.15): Class-balanced minibatches. With ~10-15 images per class per batch over 100 classes, a uniform permutation leaves per-class counts per batch highly variable. Stratified batches reduce gradient variance from class imbalance at zero compute, which may matter in a ~280-step run.
H12 (open, c=0.20): Under Muon, per-batch data composition and augmentation, not scalar optimizer knobs, may be the remaining zero-time accuracy sources. Every augmentation test (E008, E016) ran under SGD. External priors are weak: multi-sample augmentation gains on CIFAR-100 appear only at ~8,000 sample-epochs (Fort et al.), stronger translate/Cutout appears only in airbench96's 37-40-epoch recipe, and no speed recipe uses class-balanced batches. Order: H12.2 (no downside), then H12.3, then H12.1. All candidates are judged on the large-seed paired instrument (H4.6.1), because their predicted effects (~0.1 pp) are below the 22-seed resolution.
Idea: Class-balanced (stratified) minibatches at zero compute. Base: E100 code. Inside train, at the start of each epoch, build the permutation on the GPU from the global RNG, which the harness seeds per trial. Nothing is built at import or in build. Steps: (1) for each of the 100 classes, shuffle its 500 indices into a [500, 100] (rank, class) index matrix, using one argsort of random keys within class-sorted labels; (2) independently permute the class order within each rank row; (3) flatten row-major. Every consecutive block of 100 then contains each class exactly once, so a bs-1536 batch holds 15-16 images per class and a bs-1024 batch holds 10-11. The class-sorted label index is computed in prepare, which is timed. Samples, steps, shapes and augmentation are unchanged, and the net graph is untouched. Untimed check: the per-batch class-count max-min is <=1 and the epoch covers all 50,000 images exactly once. Decide on off-seed seeds 3-26 in >=3 fresh processes, paired against the E106 pooled baseline, plus two distinct scored samples.
Expected (from the queue): Time within ±0.3%, since a single argsort per epoch costs nothing measurable. Expected accuracy 0 to +0.10 pp. The pass bar is a pooled off-seed gain of >= +0.1 pp with a distinct scored mean >= 0.7543. A pass would make it a free margin source stackable on any tip and funding a ~1.5% 32 px trim. A result within ±0.05 pp closes H12.2. A loss of >= 0.1 pp would mean the batch-to-batch class variance acts as useful noise in this ~280-step regime.
