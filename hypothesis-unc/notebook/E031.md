# E031 · I044 · H2.4

H2.4 (open, c=0.10): Hard-example selection with a cheap proxy model (backprop only the highest-loss half of each batch) cuts total time even when the proxy's cost is included.
H2 (supported, c=0.85): At a fixed epoch count, the cost per epoch (systems overhead plus FLOPs per sample) is a large lever. Python and launch overhead under the 4-CPU pin, the data pipeline, precision, and input resolution can be cut by 10-25% without hurting accuracy.
Idea: Explore: proposes a new H2.4 child. Drop easy examples using free per-sample losses from the main net, with no proxy. The committee vetoed I041 for the proxy's cost; this version adds no extra forward passes. On the E023 tip, change the compiled train step to return the per-sample loss (reduction='none', then mean for backward) and scatter it into a GPU loss buffer indexed by sample id. The buffer is created and reset in prepare. From epoch 2 onward, each epoch's shuffled order uses only the 90% of samples with the highest loss in the previous pass (torch.topk on the GPU, then the usual GPU shuffle). The batch stays at 2000 and the ragged remainder is dropped. Total steps fall from 225 to about 205 (1 + 8×0.9 epoch-equivalents). The resolution phases (40/30/30), LR and Lookahead/EMA schedules are fractions of the new total step count. Alternating flip still uses each sample's own pass parity. Warm up the modified step in build with channels_last tensors, with error_on_recompile on. Judge on held-out seeds 3–12 as well as seeds 0–2.
Expected (from the queue): Time falls 8–10% (about 0.5–0.6 s), to about 5.6–5.7 s. A uniform cut of the same steps on the epoch dial would cost about 0.35 pp (held-out about 0.752). Selection is worth keeping if the held-out mean drops 0.2 pp or less (to 0.7536 or higher), so it beats the dial at better than 2.5 s/pp. A drop of 0.35 pp or more means easy examples still carry signal in 9-epoch CIFAR-100 runs (or that stale losses pick noisy or ambiguous images), which would refute this child.
