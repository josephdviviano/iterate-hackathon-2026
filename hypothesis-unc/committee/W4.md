W4 after E010. Measured: E005 (SGD+EMA, 9ep) 0.7583 @9.10s. E006 (Muon, bs2000) 0.7649 @9.45s. E007 (Muon+EMA+resize 24/28/32, 9ep) 0.7590 @7.33s. E008 (8.5ep) 0.7572 @6.98s. E009 (LR to 0) 0.7564 @6.99s, discarded. E010 (last width 512, tip) 0.7548 @6.64s.

Beliefs:
1. Time is mostly compute-bound and scales with pixels x epochs. Resizing saved about 2s. Width 512 saved about 0.35s (5%) and cost about 0.2pp, which is within my predicted range. Fixed cost (prepare, whitening, upload, first-step effects, Muon/EMA launches) is about 0.5-1s, and it caps what any one trick can gain.
2. The real gains were EMA (+1pp), Muon (+0.6pp), resizing (time -20%, accuracy -0.6pp) and width 512 (time -5%, accuracy -0.2pp). Small schedule tweaks are null (E009). Epoch cuts cost about 0.15-0.2pp per 0.5 epoch.
3. Noise. Compiled runs are near-deterministic per seed, but any recipe change reshuffles the trajectory. The 3-seed-mean accuracy noise from such changes is about 0.15-0.25pp (1 sigma). Time noise is about 1-2% (0.1s). The 40-seed mean is probably 0.1-0.3pp below the 3-seed mean.
4. Regression: the tip is at 0.7548, only 0.18pp above the 0.753 bar. It is the best of several draws, so it is probably mildly lucky. The remaining accuracy margin is nearly spent. Any further accuracy-costing change is likely to fall under the bar.
5. A more aggressive resize schedule (20 px phase) probably costs 0.4-0.8pp for about 8-12% time, which pushes the recipe under 0.753. CUDA graphs only help if the run is launch-bound. At bs2000 with 4 CPU cores I doubt it is, so I expect 0-4% gain, and some risk of failure or a hit from capturing Muon's compiled code.
6. Diagnostics such as I013 do not change the recipe. They only settle the noise estimate.

Unsure: the true 40-seed mean; whether the run is launch-bound; whether the 20 px phase hurts non-linearly.
