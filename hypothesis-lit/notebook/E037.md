# E037 · I045 · H2.3.2

H2.3.2 (open, c=0.40): FixRes-style mechanism: low-res training costs little final accuracy because the closing 32 px phase only needs to re-fit BN running statistics and the head to the test resolution. With fast BN running-stat momentum (as in Fable and airbench94_muon), that phase can be shorter. Part of E020's gain over E015 may come from this, beyond seed luck.
H2.3 (supported, c=0.70): Progressive resizing (whole-image bilinear downsampling to 24 then 28 px in early epochs, then 32 px) cuts step cost at little accuracy cost. This applies especially here, where step cost concentrates in the high-resolution group-1 layers.
H2 (open, c=0.72): Time is mainly set by per-step throughput: how fast each training step runs on the A100 (precision, memory layout, compilation, data pipeline, FLOPs per step), independent of how many steps are needed.
Idea: Exploit and test the FixRes mechanism: the closing full-res phase only needs to re-fit BN stats and the head, so it can be shorter. On the current incumbent (E030, or the low-res-epoch variant if that run is kept), move one 32 px epoch to 28 px: 2x20+3x24+3x28+3x32 (11 epochs, same LR schedule over total steps, same 4 graphs). Change nothing else. Run salt 0 and salt 1 and compare against the pooled estimate, since the expected effect is near the noise.
Expected (from the queue): Time -0.17 to -0.2 s (a 28 px epoch costs ~0.66 s vs ~0.84 s at 32 px), to about 6.75-6.8 s (-2.5%).
