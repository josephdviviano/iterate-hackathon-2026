# E018 · I020 · H2.5.1

H2.5.1 (open, c=0.45): Prediction: batching Newton-Schulz across conv weights into one call and capturing the full step (forward, backward, Muon, SGD) as a CUDA graph warmed up in build cuts train time by >=3%. 3-seed mean accuracy stays within 0.1 pp, since the change is numerically equivalent.
H2.5 (open, c=0.50): Python and kernel-launch overhead from the multi-group optimizer step (Muon Newton-Schulz per parameter, Lookahead, separate SGD groups) costs a measurable share of step time that compile flags do not reach. Capturing the train and optimizer steps in a CUDA graph, with foreach-fused updates and Newton-Schulz batched across parameters, removes it.
H2 (open, c=0.65): Time is mainly set by per-step throughput: how fast each training step runs on the A100 (precision, memory layout, compilation, data pipeline, FLOPs per step), independent of how many steps are needed.
Idea: Throughput, numerically near-equivalent. Batch Newton-Schulz across conv weights by grouping same-shape weights into one batched matmul call. Use torch._foreach ops for the SGD updates on biases, BN and the head. Capture the full train step (forward, backward, Muon, SGD) in a CUDA graph with static input buffers, and warm it up in build on synthetic data. Pass the LR schedule as a GPU tensor so per-step LR changes need no recapture. prepare resets all parameter and state tensors in place.
Expected (from the queue): Train time -3 to -6%, about -0.25 to -0.5 s, removing most of the ~4% Muon overhead and Python launch cost. 3-seed mean accuracy stays within 0.1 pp of 0.7544. If the gain is <1%, launch overhead is not the bottleneck and H2.5 is weakened.
