# E026 · I032 · H4.2

H4.2 (open, c=0.25): Optimizer choice: Muon on conv filters, which set the CIFAR-10 record, does not beat tuned Nesterov SGD on the airbench96 net for CIFAR-100. Prior evidence leans toward refutation, so this is low-priority and needs only one decisive check.
H4 (open, c=0.60): The airbench96 CIFAR-10 hyperparameters were tuned for 37 epochs and are mis-tuned for a ~10-11 epoch 100-class run. Re-tuning regularization (E004 +1.26 pp; E011 translate 2) raised accuracy at fixed epochs. The regime is sample-limited, not step-limited (E015), so batch size is a throughput lever, not an accuracy lever. Schedule constants (whiten_bias_epochs 3, warmup from 0.2x, decay to 0, cubic Lookahead ramp) remain untested at this budget.
Idea: Exploit: make Muon cheap at equal math. Start from E025 (commit 50d39d6: E024 tip plus Muon on the block conv filters, lr ~0.24, momentum 0.6, nesterov; 0.7622 at 7.26 s). Change only how the Muon update is implemented, not what it computes. (a) Group the same-shape conv filters (block-2 conv2/conv3, block-3 conv2/conv3, and any others that match) and run Newton-Schulz on each stacked group as one batched bf16 bmm. (b) Put the whole Muon step (momentum update, nesterov blend, NS, renorm, param update) into the same compiled function as the fused foreach SGD+Lookahead update, inside the CUDA-graph-captured train step. Read the LR from the GPU step table. Momentum buffers stay persistent, are captured in build on synthetic data, and are zeroed in prepare. Check in a short synthetic test that the parameter delta matches E025's per-parameter loop to bf16 tolerance.
Expected (from the queue): The ~2.3 ms/step of Muon overhead falls to ~0.6-1.0 ms/step, the NS matmul floor (a 704x6336 NS is ~0.25 ms). Time drops from 7.26 s to ~6.65-6.85 s. Accuracy is unchanged within noise at ~0.758-0.765. If time is <= 6.45 s it is a new best outright. Otherwise it is the base for the Muon epoch cut, where each epoch saved is worth ~0.6 s. If time stays > 7.0 s, NS compute rather than launch overhead dominates, and the next thing to try is fewer NS iterations.
