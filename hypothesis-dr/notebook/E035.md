## Post-mortem
<!-- For failures and missed predictions: what you predicted, what happened, the root cause,
what the world model got wrong, the lesson. -->
Time predicted [5.90, 6.10]; got 6.18. Root cause: the build() warmup for the recal path used x.repeat(...), which returns
a contiguous NCHW tensor, while train() feeds channels_last slices. The first real recal call then hit fresh cuDNN
benchmark autotuning (and/or a new stride specialisation) inside the timed region of trial 0 (+0.6 s); my offline
diagnostic showed the same first-call excess (+0.3 s), but I misread it as a generic "first train() in process"
effect. The steady-state cost (+0.1 s, 1.7%) was also above my 1.4% estimate. Lesson: warm up with tensors of the
exact shape AND memory layout used in the timed path, and compare trial-0 vs later-trial times in diagnostics;
a first-call excess that appears only for the new path is a warmup gap, not noise.
