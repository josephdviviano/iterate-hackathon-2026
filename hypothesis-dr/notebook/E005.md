# E005 · I009 · H2.2.1

H2.2.1 (open, c=0.40): On top of H2.1, a fused/foreach optimizer plus a single compiled train step (forward, backward and update) reduces time by >=8%, with accuracy within 0.2 pp.
H2.2 (open, c=0.50): Hiverge-style engineering cuts the remaining per-step overhead in a run of a few seconds: a vectorized or fused optimizer update (foreach/fused, or batched Muon), a fully compiled train step, and SiLU instead of GELU.
H2 (open, c=0.60): With the recipe and epochs held fixed, per-step GPU efficiency is a major share of what remains of the time. That covers precision, memory format, kernel fusion and optimizer or Python launch overhead. Systems work can cut time by 10-30% with no change in accuracy.
Idea: Built on the first feasible airbench96-style base (I001/I003 knee). Make one systems change and leave the recipe alone. Move the whole training step into one torch.compile'd function: forward, backward, Nesterov SGD update and lookahead blend. Apply the update with torch._foreach_* ops (or SGD foreach/fused=True) so there is no per-parameter Python loop. Pass lr and the lookahead schedule as 0-d GPU tensors so changing them never triggers a recompile. Compile and warm up this function in build() on synthetic data, covering the full batch and the final partial batch. Keep the epoch count, seeds, lr, wd, LS and widths identical to the base.
Expected (from the queue): Time drops about 5-10% against the base at the same epoch count, because Python and kernel-launch overhead is a noticeable share of a run near 10 s. Accuracy stays within 0.2 pp of the base, so feasibility is unchanged. If the gain is under 3%, the step was not launch-bound and H2.2 loses support.
