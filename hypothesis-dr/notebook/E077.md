## Post-mortem
<!-- For failures and missed predictions: what you predicted, what happened, the root cause,
what the world model got wrong, the lesson. -->
Predicted bit-identical accuracy; got a full re-draw (-0.25/+0.14/-0.84 pp per seed). The world model (E003, I102) said
"identical commits rerun bit-identically", but that is not guaranteed: this exact code reproduced E069 offline, then
re-drew in the harness process. Root cause: timing-based autotuning (cudnn.benchmark, Inductor max-autotune) can pick
different kernels in different processes; any build()-time difference (allocator state, warmups, as I106's warm-prepare
variants also showed) shifts the choices, and different kernels round differently. Over ~200 chaotic steps that gives a
full per-seed re-draw. Lesson: NO change is accuracy-neutral on the 3-seed gate. Every run is a draw with
3-seed-mean sd ~0.15-0.25 pp around the recipe's true mean (~0.7534 for E069). The tip's 0.7561 is a lucky draw, and
time-only improvements pass the 0.753 gate only ~50% of the time.
